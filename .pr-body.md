## Summary

Adds three window-state mutators to the `Webview` API surface, symmetric with the existing `maximizeWindow()`, `minimizeWindow()`, and `fullscreen()`:

- `unmaximizeWindow()` — inverse of `maximizeWindow()`
- `unminimizeWindow()` — inverse of `minimizeWindow()`
- `setFullscreen(boolean on)` — idempotent counterpart to `fullscreen()`

Implemented on all three backends (Cocoa/macOS, Win32/WebView2, GTK4/WebKitGTK).

## Motivation

I'm building [Jauri](https://github.com/priand/Tauri4J), a Java-native alternative to Tauri v2 on top of `avaje-webview`. To implement Tauri's `plugin:window|unmaximize`, `|unminimize`, and `|set_fullscreen` commands faithfully, the underlying webview needs to expose inverses for its existing one-way primitives — otherwise these commands can only be emulated with shadow state that goes stale the moment the user resizes via the OS titlebar.

## Backend notes

**macOS (`MacOSHelper`, `CocoaWebView`)** — `-[NSWindow zoom:]` and `-toggleFullScreen:` are AppKit *toggles*, so the impls guard on `-isZoomed` (BOOL → `JAVA_BYTE`) and `styleMask & NSWindowStyleMaskFullScreen` (bit 14, `NSUInteger` → `JAVA_LONG`) to *assert* state rather than invert it. `-deminiaturize:` is safe to call unconditionally.

**Windows (`Win32`, `Win32WebView`)** — `unmaximize`/`unminimize` both map to `ShowWindow(hwnd, SW_RESTORE)`. `setFullscreen(false)` is more involved: `fullscreen()` strips `WS_OVERLAPPEDWINDOW` and covers the monitor, so reversing it requires remembering the pre-fullscreen style and rect. `Win32WebView` now records `savedStyle` + `savedX/Y/W/H` in `enterFullscreen()` via `GetWindowRect` + `GetWindowLong`, then replays them in `exitFullscreen()` via `SetWindowLong` + `SetWindowPos` with `SWP_FRAMECHANGED`. An `isFullscreen` guard makes both entries idempotent.

**Linux (`Gtk4`, `LinuxHelper`, `GtkWebView`)** — 1:1 FFM wrappers around `gtk_window_unmaximize`, `gtk_window_unminimize`, and `gtk_window_unfullscreen`. GTK no-ops these when the target state isn't active, so no bookkeeping is required.

## API additions

```java
public interface Webview {
  // existing...
  Webview maximizeWindow();
  Webview fullscreen();
  Webview minimizeWindow();

  // new
  Webview unmaximizeWindow();
  Webview setFullscreen(boolean on);
  Webview unminimizeWindow();
}
```

Nothing in the existing surface changes.

## Scope

Deliberately narrow: only the three P0 primitives above. Window-state *getters* (`isMaximized`, `isMinimized`, `isFullscreen`, `title`, `innerSize`) and additional mutators (`show`/`hide`/`focus`/`setPosition`) that Jauri also needs are deferred to follow-up PRs to keep this one reviewable.
